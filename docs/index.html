Formula Substitution Engine A + B → C · C → A + B

Perfume formulas change all the time. A material gets banned, goes over a limit, gets too expensive, or a client doesn't want it. This engine does the two jobs that come up most, and both run on O(1) HashMap look-ups:

A + B → C · consolidateTwo raw materials that a ready-made accord already covers get swapped for that one accord. Fewer weigh-ins.
C → A + B · replaceAn ingredient you can't or don't want to use gets swapped for a blend of alternatives with a similar effect.

02Replace unwanted ingredients · C → A + B

Every ingredient has a limit: banned (0%), restricted (a maximum %), or no limit. You can also avoid anything yourself, for example a material that's too expensive, out of stock, or that a client doesn't want. The engine keeps what's allowed and gives the rest to a substitute blend. A substitute blend is only used if its own ingredients are allowed. Otherwise the next option is tried, so one problem is never swapped for another.

05How it works in Java

The core is plain Java with no framework code, so it is easy to unit-test. Spring Boot wraps it with a REST API and the SQL database. Reformulation runs replace first, then consolidate. The consolidation step is told never to fold a banned, restricted or avoided ingredient into an accord.
